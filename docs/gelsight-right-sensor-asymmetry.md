## 2. 原因

### 2.1 USD アセットの取り付けが非対称

`Robots/Franka/GelSight_Mini/Gripper/physx_rigid_gelpads.usd` を直接読んで計測した。

| プリム | 中点からの変位 [mm] | 対称性 |
|---|---|---|
| `gelsight_mini_case_left/right`（＝カメラ） | ±22.3945, ∓22.3944, ∓0.0013 | **1.3µm で鏡像対称** |
| `gelpad_left/right` | ±5.3762, ∓5.3206, **∓0.2181** | **436µm ずれている** |

カメラ座標系で見た gelpad 原点までの距離:

```
left  24.255 mm
right 23.964 mm     ← 0.291 mm の差
```

**メッシュ自体は同一**（点数 10,248・bbox 16.67×16.67×25.25mm がどちらも一致）。形は同じで取り付け位置だけが違う。

### 2.2 高さマップは深度をそのまま使う（補正なし）

`tacex/gelsight_sensor.py`:

```python
self._data.output["height_map"][:] = self.camera.data.output["depth"][:, :, :, 0]
self._data.output["height_map"] *= 1000          # m -> mm
```

per-sensor のキャリブレーションが無いので、幾何のずれがそのまま高さマップのオフセットになる。

**実測で確認した**（`hm_probe_signals.npz`・arm=off・4env・150step）:

```
ゲル表面までの最短距離   left 27.8707 mm / right 28.1332 mm
基準値の差 (right - left) = +0.2688 mm （初期）／ +0.2625 mm（平均）
USD からの予測            =  0.291 mm
```

**大きさが 8% 以内で一致する。** 符号が反転するのはパッドが鏡像取り付けだから。

### 2.3 Taxim の押し込み量が左右共通の定数を引く

`tacex/simulation_approaches/gpu_taxim/taxim_sim.py`:

```python
dist_obj_sensor_case = min_distance_obj - self.cfg.gelpad_to_camera_min_distance
dist_obj_sensor_case = torch.where(dist_obj_sensor_case < 0, 0, dist_obj_sensor_case)
self._indentation_depth[:] = torch.where(
    dist_obj_sensor_case <= self.cfg.gelpad_height,
    (self.cfg.gelpad_height - dist_obj_sensor_case) * 1000, 0
)
```

`gelpad_to_camera_min_distance = 24.0 mm`、`gelpad_height = 4.5 mm`。**どちらも左右共通の定数**で、実測の取り付け位置を反映しない。

∴ `min_depth >= 28.5 mm` になると押し込み量は **0（接触なし）** に切り捨てられる。

## 3. 定量

実測の高さマップに上の式を適用して再計算した。

| | 最短距離 | dist_obj_case | 押し込み量 mean | 0 になった step | 境界 28.5mm までの余裕 |
|---|---|---|---|---|---|
| 左 | 27.8707 mm | 3.8707 mm | **0.6293 mm** | 0/150 | 0.6293 mm |
| 右 | 28.1332 mm | 4.1332 mm | **0.3682 mm** | 2/150 | **0.3668 mm** |

- 押し込み量の比 **left/right = 1.71**
- 触覚画像の std の比は 2.88 — Taxim の描画が非線形なので 1.71 倍の入力差が 2.9 倍の出力差に増幅される
- **右は境界まで 0.37mm しか余裕がない**。少し離れるだけで「接触なし」に落ちる

### 反実仮想（決定的）

右の高さマップから実測のオフセット 0.2688mm を引いて再計算する。

```
補正前  押し込み量 0.3682 mm   left/right = 1.71
補正後  押し込み量 0.6356 mm   left/right = 0.990
```

**補正すると左右がほぼ完全に一致する（比 0.99）。** 0.29mm の取り付けずれだけで症状のすべてが説明できる。

## 3.5 影響が出るのは接触後だけ（peg-in-hole-29 の独立検証・2026-08-20）

**重要な限定。** 非対称は**エピソード全体で見たとき**に出るもので、**接触前の窓では消える**。

`p27_collect_b0-3` の `tactile_raw_all` を窓を変えて集計した結果（peg-in-hole-29 による実測）:

| 窓 | 左 std | 右 std | 左/右 |
|---|---|---|---|
| 全 60 step | 0.01175 | 0.00548 | **2.14** |
| step 0–7（plan27 の主判定窓） | 0.00291 | 0.00303 | **0.96** |

step 0–7 では env 単位の比の中央値 **0.96**（p05 0.84 / p95 1.09）で、**128env 中 85env は右が左を上回る**。
床張り付き画素（時間 std < 1e-4）も **左 35.4% > 右 29.1%** で、この窓では右のほうが「生きて」いる。

**これは §3 の機構と整合する（むしろ支持する）**:

1. 接触前は把持荷重だけなので、押し込み量が小さく**両センサとも線形域** → 対称
2. 接触で荷重が増えると、余裕 0.37mm しかない**右が先に飽和** → 非対称

∴ **非対称は「センサが壊れている」のではなく「レンジを使い切っている」現れ。**

### 判定への含意

| 対象 | 評価窓 | 非対称の影響 |
|---|---|---|
| plan27 の陰性判定（AUC 0.5062 / 0.5532） | step 0–7 | **無い**（比 0.96）。この非対称では説明されない |
| plan22 / plan24 の学習・評価 | 150 step 全体 | **ある**（比 2.1 の領域を含む） |

**plan27 の結論はこの発見の影響を受けない。** 判定窓では両センサがほぼ同等に応答したうえで
δ が読めなかった、というのが実態。

### チャネル順の確定

`patches/tacex/0003-tactile-observation-wiring.patch` のコードで確定している。

```python
left  = self.gsmini_left.data.output["tactile_rgb"]     # -> ch 0-2
right = self.gsmini_right.data.output["tactile_rgb"]    # -> ch 3-5
return torch.cat([left, right], dim=-1)
```

`gsmini_left.prim_path = ".../gelsight_mini_case_left"` なので **ch0-2 が物理的な左**。
高さマップの実測（`gsmini_left` 27.87mm / `gsmini_right` 28.13mm）とも整合する。

## 7.5 追加調査（2026-08-20・GPU 不要の解析）

### 深度カメラが見ているのはペグ。ゲルパッドではない

高さマップ（＝カメラ深度）を画像として可視化した。写っているのは**ペグの断面（水平の帯）**で、
`clippingRange=(20,29)mm` の外は 29.0 に丸められて「何も無い」になる。

| | 可視画素の割合 | 可視領域の重心 col（中心 15.5） | 最短距離 |
|---|---|---|---|
| 左 | **17.32%** | 16.69 | 27.8707 mm |
| 右 | **11.39%** | **11.68** | 28.1332 mm |

**右カメラはペグを画面の端に寄せて捉えており、写る面積が左の 2/3 しかない。**
これが感度差の直接の姿。

### ゲルパッドの位置は出力に一切影響しない（決定的）

env 数・seed・δ を完全に揃えて、右ゲルパッドの移動量だけを変えた3条件を比較した。

| 移動量 | 高さマップ | 判定 |
|---|---|---|
| 0 mm | 基準 | — |
| 0.55 mm（対称化） | **ビット完全一致** | 変化なし |
| 11 mm（20倍） | **ビット完全一致** | 変化なし |

**11mm 動かしても何も変わらない。** ∴ ゲルパッドは深度カメラから見えていない。
§2.1 の非対称は実在するが、センサ出力とは**無関係**。

> 途中で「11mm では変化した」と判断した比較があったが、**env 数が違う（4 vs 2）ラン同士を
> 比べていた誤り**だった。env 数が変わると軌跡が再現しないことは §6.8 に既出。

### カメラの向きは対称。指先フレームもほぼ中央

| 測定 | 結果 |
|---|---|
| カメラが中点 M を捉える位置（ローカル） | 左右とも光軸から **0.0013mm** ＝ 完全対称 |
| 画角換算で予想される可視領域の重心 | 左右とも col **16.00** |
| `panda_fingertip_centered` の左右軸ずれ | **0.0824mm**（左カメラ寄り） |

**予測は左右とも col 16.00。実測は左 16.69・右 11.68。左だけが予測どおりで、右が説明できない。**

### 残る候補（未検証）

1. ペグが実際に左寄りに保持されている（物理）。指先フレームのずれ 0.08mm では 0.26mm を説明できない
2. 右カメラの視野が何かに遮られている（指など）
3. 片方のカメラに固有の描画上の問題

**切り分けには実行時のカメラ姿勢とペグ姿勢を物理側から取る必要がある**（USD の authored 姿勢では
足りない。§9 参照）。GPU が要るので未実施。
